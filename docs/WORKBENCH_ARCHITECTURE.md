# 个人投资工作台架构草案

这份文档先定义方向，不要求一次性完成重构。当前项目已经从“选股脚本”扩展到行情、数据维护、Web 控制台和未来 agent 出口，更合适的定位是个人投资工作台。

## 设计目标

- 数据可信：MySQL 作为主数据源，所有页面和 agent 都围绕同一套数据工作
- 工作流闭环：数据同步、行情查看、策略研究、任务记录、结论沉淀都能在一个入口完成
- 模块清晰：行情、策略、任务、agent 不互相硬耦合
- 可审计：重要动作都写入任务表或运行日志，方便回看和复盘
- 可扩展：未来可以接入投资助手 agent，而不需要推倒现有 Web 和数据库

## 建议分层

```text
Web UI
  |
API / Service Layer
  |
Domain Modules
  |-- Data Sync
  |-- Market Data
  |-- Strategy Research
  |-- Portfolio / Watchlist
  |-- Agent Tools
  |
MySQL + Local Cache + Reports
```

### 1. 数据层

职责：

- 股票基础信息
- 日线行情
- 停复牌信息
- 估值、分红、财务摘要
- 同步任务和同步明细

当前基准：

- MySQL 是主库
- `data/daily_store/` 可以作为本地文件缓存或备份
- `data/cache/` 可以继续保存第三方接口缓存
- `sync_runs` 和 `sync_run_items` 是任务状态和审计入口

后续建议：

- 为重要表补充数据来源字段和更新时间
- 区分 raw 数据、清洗后数据、派生指标
- 后台任务每次运行都记录参数、状态、错误样本和耗时

### 2. 行情模块

职责：

- 股票搜索
- 股票画像
- K 线查询
- 指标查询
- 自选股和关注列表

当前已实现：

- 代码或名称搜索股票
- 从 MySQL 读取日 K 数据
- Web 页面绘制本地 K 线图

后续建议：

- 支持复权切换
- 支持 60/120/250 日区间
- 支持 MA、成交量、涨跌幅、换手率
- 增加自选股分组和股票笔记
- 增加“最近更新状态”，提示某只股票数据是否已同步到最新交易日

### 3. 策略研究模块

职责：

- 选股规则
- 策略参数
- 回测
- 候选池解释
- 结果归档

当前状态：

- 已有一个简单的日终选股策略
- 已有轻量级回测框架

后续建议：

- 把策略从函数参数升级成可配置规则
- 保存每次选股运行和结果
- 增加策略解释字段，比如为什么入选、为什么排除
- 支持多个策略并排比较
- 支持把策略结果加入观察列表，而不是直接当成交易建议

### 4. 任务系统

现在 Web 里的同步任务仍然是同步请求模型，用户会看到页面一直等待。工作台化之后，建议把所有长任务改成后台任务。

建议状态：

- `queued`
- `running`
- `completed`
- `partial_failed`
- `failed`
- `cancelled`

建议能力：

- 启动任务后立刻返回 `run_id`
- 页面轮询任务状态
- 最近任务可以查看详情、错误样本、处理数量
- 支持取消仍在排队或运行中的任务
- agent 调用任务也复用同一套任务表

### 5. 投资助手 Agent 出口

未来 agent 不建议直接随意读写所有表，而是通过受控工具接口进入工作台。

建议工具类型：

- `search_stock`：搜索股票
- `get_stock_quote`：读取行情和 K 线
- `get_sync_status`：查看数据同步状态
- `run_screen`：运行指定选股策略
- `explain_candidate`：解释某个候选股
- `create_watch_note`：写入股票观察笔记
- `create_task`：创建后台研究任务

建议边界：

- 只读工具可以默认允许
- 写入工具需要记录来源和参数
- 高风险动作需要人工确认
- agent 输出结论要能追溯到数据、参数和时间

### 6. Web 信息架构

建议把页面从单页堆叠逐步演进成几个区域：

- 总览：数据库状态、最近任务、今日提醒
- 行情：搜索、K 线、股票画像、自选股
- 策略：选股、回测、策略运行记录
- 数据：同步任务、失败样本、数据覆盖率
- 助手：agent 对话、工具调用记录、研究任务
- 笔记：股票观察、策略复盘、投资假设

短期可以继续保持单页面，但视觉和 API 要按这些区域分组。

## 建议代码演进

当前目录：

```text
src/
  quant_backtest/
  quant_web/
```

建议逐步演进为：

```text
src/
  quant_data/
    sources.py
    sync.py
    repositories.py
  quant_market/
    quotes.py
    indicators.py
    watchlist.py
  quant_strategy/
    screens.py
    backtests.py
    rules.py
  quant_tasks/
    runner.py
    models.py
    status.py
  quant_agent/
    tools.py
    context.py
    audit.py
  quant_web/
    app.py
    routes.py
    views.py
```

迁移原则：

- 不为了目录漂亮而重构
- 每次新功能优先放进正确边界
- 旧代码在触碰时顺手迁移
- 数据库访问集中到 repository/service 层
- Web 层只做请求解析、响应组装和页面呈现

## 分阶段路线

### 第一阶段：工作台定位明确

- README 和架构文档改成投资工作台定位
- Web 首页标题和说明调整
- 保留现有选股，不再把它当成唯一核心

### 第二阶段：行情和自选股

- 完善 K 线图
- 增加自选股
- 增加股票笔记
- 增加单股数据更新状态

### 第三阶段：后台任务

- 增量同步改成后台任务
- 选股和回测改成后台任务
- 页面展示任务状态、日志和错误样本

### 第四阶段：策略研究

- 策略规则配置化
- 选股结果归档
- 策略解释和候选股对比

### 第五阶段：Agent 接入

- 定义 agent 工具协议
- 增加工具调用日志
- 支持 agent 发起研究任务
- 支持 agent 基于工作台数据做复盘和解释

## 当前最值得先做的三个改动

1. 把 Web 的同步任务改成后台任务，避免页面长时间等待。
2. 增加自选股和股票笔记，让行情模块从“能看”变成“能跟踪”。
3. 给 agent 预留工具层，不让未来 agent 直接绕过服务层读写数据库。
